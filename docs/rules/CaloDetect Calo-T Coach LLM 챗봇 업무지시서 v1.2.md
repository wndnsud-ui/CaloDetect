## 변경 요약 (v1.1 → v1.2)

v1.2는 develop 브랜치의 기존 채팅을 플로팅 채팅창으로 옮기고, 해석기를 LLM으로 바꾸며, 챗봇 기능 범위 제한을 모두 푼다.

| 항목 | v1.1 | v1.2 |
| --- | --- | --- |
| 출발점 | 새 챗봇 개발 | develop `ChatRecord` · `ChatConsumptionEdit` 이식 |
| 문장 해석 | 미정 (develop은 규칙 기반, 전체 일치만) | LLM 필수 |
| 기능 범위 | Intent 7종, MVP 4단계 | 범위 제한 없음, 새 Intent 계속 추가 가능 |
| 일반 대화 | `general_chat` 최소 대응 | 자유 대화 허용 |
| 음식점 검색 | 우선순위 4, 지도 API 이후 | 카카오 지도 API, 1차는 설정만 |
| 명칭 | Calo-T Coach / 칼로티 코치 | Calo-T Coach / 칼로티 코치로 통일 (코드의 "칼로T코치" 교체) |
| 출력 형식 | `follow_up` 문자열 1개 | `quick_actions` 배열 + 카드 수치는 서버가 붙임 |

## 기본 방향

develop 채팅은 화면과 저장 로직을 그대로 쓰고, 위치와 해석기만 바꾼다.

1. **위치 이동**: `ChatRecord.jsx`(채팅 페이지)와 `ChatConsumptionEdit.jsx`(섭취량 수정 모달)를 하나의 플로팅 채팅 시트로 합친다. 별도 페이지로 이동하지 않는다.
2. **스타일 유지**: 말풍선·칩·음식 카드·입력창은 `chat-record.css`를 그대로 쓴다.
3. **해석기 교체**: `chat_interpret.py`의 `interpret_chat()`(규칙, 전체 일치)을 LLM 해석기로 바꾼다. LLM 결과는 지금 해석기와 같은 형식(`intent`, `updates`, `clarification_reason` 등)으로 내고, `source`는 `'llm'`으로 표시한다.
4. **서버 로직 유지**: 비율 적용(`resolve_updates`), 음식 카탈로그 매칭, kcal · 영양 계산, 저장은 기존 코드를 그대로 쓴다.
5. **LLM 필수**: 모든 사용자 문장은 LLM을 거친다. 규칙 해석기는 LLM 장애 때만 쓰는 비상용으로 남긴다.

## 확장 기능 범위

챗봇이 다룰 수 있는 기능에는 상한을 두지 않는다. 아래는 현재 목록이며, 서비스에 기능이 생기면 Intent를 계속 추가한다.

| Intent | 기능 | 연결되는 기존 기능 |
| --- | --- | --- |
| `meal_record` | 사진·문장으로 식사 기록 | develop A1 채팅 기록, 음식 인식 |
| `meal_record_edit` | 섭취량·음식·끼니·날짜 수정, 삭제, 되돌리기 | develop A0 섭취량 수정 |
| `food_info` | 음식 · 영양정보, 음식끼리 비교 | 영양 DB |
| `meal_recommend` | 오늘 뭐 먹지, 조건별 추천 | 식사 추천 |
| `user_meal_analysis` | 오늘 · 최근 7일 · 한 달 분석, 식습관 코칭 | 식단 분석, `/analytics/month` |
| `goal_setup` | 목표 칼로리 · 매크로 목표 조회와 변경 | 목표 설정 |
| `exercise` | 운동 기록, 운동 제안 | (신규) |
| `reward_info` | 포인트 · 레벨 · 미션 · 리워드몰 안내 | 리워드, 지방이 성장 |
| `jibang` | 지방이 꾸미기 · 방 · 보상 안내 | 지방이 방, 옷 |
| `community` | 글 요약, 식단 공유 도우미 | 커뮤니티 |
| `restaurant_search` | 주변 음식점 검색 | 카카오 지도 API (1차는 설정만) |
| `navigate` | "식단 분석 보여줘"처럼 화면 이동 | 앱 내 화면 전체 |
| `general_chat` | 자유 대화, 동기부여, 잡담 | 지방이 말투 |

풀리는 제한:

- develop의 "정해진 표현과 전체 일치해야만 알아듣는다" 규칙을 없앤다. 자유로운 문장, 오탈자, 줄임말도 알아듣는다.
- 한 문장에 여러 요청이 있으면 한 번에 처리한다. 예: "찌개는 다 먹고 밥은 반, 저녁 추천도 해줘"
- MVP 단계 구분 없이 기능을 동시에 개발할 수 있다.
- 챗봇은 로그인한 사용자만 쓸 수 있다. 비로그인 상태에서 지방이 버튼을 누르면 로그인을 안내한다.

## Structured Output v1.2

LLM은 문장과 선택만 내고, 카드에 나오는 수치는 서버가 `food_id`로 붙인다. 요청 여러 개는 `actions` 배열로 받는다.

**LLM 출력** (서버가 검증하기 전)

```json
{
  "actions": [
    {"intent": "meal_record_edit", "food": "쌀밥", "action": "update_amount", "consumption_ratio": 0.5},
    {"intent": "meal_recommend", "meal_type": "dinner", "cuisine": "korean", "taste": "spicy"}
  ],
  "answer": "쌀밥을 50%로 바꿀어요. 저녁은 단백질 있는 매콤한 한식이 좋아 보여요.",
  "recommendations": [{"food_id": 310, "reason": "단백질이 많고 매콤해요."}],
  "quick_actions": [
    {"label": "국물 없는 걸로", "text": "국물 없는 메뉴로 다시 추천해줘"},
    {"label": "되돌리기", "action": "undo"}
  ],
  "needs_confirm": true
}
```

**화면에 보내는 응답** (서버가 수치를 붙인 뒤)

- `recommendations[]` → 서버가 `name`, `calorie`, `protein` 등을 DB 값으로 채운다. 후보 목록에 없는 `food_id`는 버린다.
- `actions[]` → 기록을 바꾸는 항목은 `needs_confirm`이면 "맞아 / 아니야" 확인 뒤 저장하고, 비교 카드(수정 전→후)를 함께 내려준다.
- `quick_actions[]` → 말풍선 아래 버튼. `text`는 누르면 사용자 문장으로 보내고, `action`은 바로 실행한다.
- 양을 모르는 경우 → `consumption_ratio: null` + `quick_actions`에 "1/4 · 절반 · 3/4 · 직접 입력".

## UI

앱의 모든 화면 오른쪽 아래 같은 자리에 지방이 플로팅 버튼을 두고, 누르면 같은 화면 위로 채팅 시트가 올라온다. 시안: [Calo-T Coach 챗봇 시안](https://claude.ai/artifact/8cJvRAx9EaK9JVp4pWrsF3)

- **플로팅 버튼**: 지방이 `front.png`, 흰 원 + `#00836D` 테두리. 첫 진입 때는 Gaegu 말풍선 힌트("뭐 먹을지 고민돼요?")를 뛰운다. 버튼은 각 페이지가 아니라 앱 최상위(shell)에 한 번만 두고 position: fixed로 고정해, 어느 화면에서 눌러도 같은 채팅이 열린다. 그 자리는 항상 비워 두도록 모든 화면 하단에 버튼 높이만큼 여백(약 100px)을 확보한다. 채팅이 열려 있을 때, 카메라 촬영 화면처럼 화면 전체를 쓰는 모달에서만 숨긴다.
- **홈 히어로 지방이**: 눌러도 채팅이 열리게 해서 진입점을 두 개로 둔다.
- **시트 상단**: 지방이 얼굴(`f_happy.png`) + "칼로티 코치 · 지방이" + 상태 문구. 아래로 끌거나 닫기 버튼으로 접는다.
- **대화 영역**: develop `chat-record.css`의 말풍선 · 음식 카드 · 비율 배지 · 칩을 그대로 쓴다. 추천은 세로 음식 카드 + \[기록\] 버튼.
- **입력창**: 사진 버튼 + 입력창 + 전송. Placeholder는 "오늘 뭐 먹을지 물어보세요."
- **빠른 질문**: 오늘 뭐 먹지? · 오늘 식사 어땠어? · 단백질 많은 메뉴 추천 · 가볍게 먹을 메뉴 · 방금 음식 기록 수정
- **대화 유지**: 시트를 닫았다 열어도 같은 대화가 이어진다(develop의 `/chat/conversation` 재사용).

* **로그인**: 비로그인 상태에서 버튼을 누르면 채팅 대신 "로그인하면 지방이와 대화할 수 있어요" 안내와 \[로그인 / 회원가입\] 버튼을 띄운다.
* **개인정보 고지 팝업**: 채팅을 처음 열 때 한 번만 띄운다. "더 정확한 답변을 위해 식사 기록과 대화 내용이 외부 AI(LLM)로 전송돼요." + \[동의하고 시작\]. 동의 전에는 대화할 수 없고, 동의 여부와 시각을 계정에 저장해 다시 띄우지 않는다.
* **하루 5회 제한**: 입력창 위에 "오늘 남은 질문 3/5"를 보여준다. 다 쓰면 입력창을 막고 "오늘 질문을 다 썼어요. 내일 다시 만나요!"를 띄운다. 횟수는 한국 시각 0시에 초기화하고 서버가 셈다.

## 유지하는 원칙

기능 범위는 다 풀되, 아래 원칙은 제한이 아니라 답이 틀리거나 기록이 망가지지 않게 하는 최소 장치라 남긴다.

**데이터 정확성**

- 칼로리 · 영양성분 수치는 서버 계산 값만 보여준다. LLM이 숫자를 만들지 않는다.
- 기록을 바꾸는 요청은 서버가 카탈로그와 기록에 있는 음식인지 확인한 뒤 적용한다.
- 사용자가 말하지 않은 양은 정하지 않고 선택지로 되묻는다.
- 추천 음식은 DB에 있는 것만, 음식점은 지도 API가 돌려준 것만 보여준다.
- 자유 대화는 막지 않되, 서비스에 없는 기능을 있다고 안내하지 않는다.

**건강 안전**

- 질병을 진단하거나 치료 · 약 복용을 지시하지 않는다. 관련 질문은 일반 정보와 함께 전문가 상담을 권한다.
- 극단적인 단식 · 과도한 제한을 권하지 않는다. 목표 칼로리를 지나치게 낮추는 요청은 우려를 전하고 확인한다.

**운영**

- 서버 오류 내용 · Stack Trace를 화면에 보여주지 않는다. LLM 오류는 "지금 답변을 만들지 못했어요. 다시 질문해주세요."

## 구현 단계와 테스트

순서는 이식 → LLM 교체 → 기능 확장이며, 3단계부터는 기능별로 병렬 개발한다.

1. **이식**: develop 채팅 페이지와 수정 모달을 플로팅 시트로 옮긴다. 이 단계에서는 규칙 해석기 그대로.
2. **LLM 교체**: `interpret_chat()` 자리에 LLM 해석기를 넣고, 기존 규칙 테스트가 모두 통과하는지 확인한다.
3. **기능 확장**: 추천 · 분석 · 목표 · 운동 · 리워드 · 화면 이동 · 자유 대화를 붙인다.
4. **외부 연동**: 카카오 지도 API는 1차에 앱 키 · 도메인 등록 · 환경변수 설정만 해 두고, 이후 `restaurant_search`를 연다.
