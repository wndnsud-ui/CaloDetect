# CaloDetect 2.0 — 확장 업무지시서 v5.3 · 이미지 시안 반영

작성일: 2026-10-07 · 용도: 화면 기획, 내부 실험 계획, 후속 구현 지시

## 1. 문서 적용 범위

사용자 요청인 “이미지 시안을 참고하고 업무지시서 확장”에 따라 작성한 별도 확장본이다. 이번 산출물은 업무지시서이며 서비스 코드 구현이나 배포를 지시한 것으로 해석하지 않는다.

참고 자료:

- 사용자 첨부 이미지: 상단 WEB APP 8개 화면, 하단 WEBSITE 6개 구성.
- 사용자 추가 이미지: 왼쪽 WEB APP 9개 화면, 오른쪽 WEBSITE 4개 구성. 이하 각각 시안 A·시안 B로 구분한다.
- 사용자 제공 `CaloDetect_2.0_Codex_업무지시서_v5_2_확장실험판.md`: 내부 실험 아이디어와 모델 비교 계획.
- [공식 Master Spec v11](../rules/CaloDetect_Codex_통합_업무지시서_20261002_v11.md), [개발 규칙](../rules/DEVELOPMENT_RULES.md), [결정 대기 사항](../rules/PENDING_DECISIONS.md), [변경 이력](../../CHANGELOG.md).

첨부 문서의 “구현 허용”, “최종 명령”은 참고 문서 내부의 지시다. 현재 사용자가 요청한 문서 확장과 구분한다. 이 문서는 Master Spec 원문을 대체하지 않으며 공식 P0 범위를 확대하지 않는다. 후속 구현 시 명시적 사용자 지시와 이후 확정된 결정을 먼저 확인한다.

서비스 표시명은 `CaloDetect`. `2.0`, `v5.3`, `EXP`는 내부 문서에서만 사용한다.

## 2. 제품 방향과 단계

핵심 흐름은 음식 사진 → 탐지 → 확인·수정 → 섭취량 → 영양 계산 → 식단 저장 → 상태 확인 → 식사 추천 → 실제 기록이다. 지방이는 이 흐름을 안내하고 기록 습관을 친근하게 보여주는 캐릭터다.

## 4. 앱 공통 화면 규칙

모바일의 제안 메뉴는 홈 / 식단 / 분석 / 추천 / 내 기록이다. 중앙 분석 버튼은 사진 입력으로 연결한다. 지방이 꾸미기는 홈 위젯 또는 내 기록에서 진입한다. 알림과 북마크는 실제 기능이 확정되기 전 활성 버튼으로 표시하지 않는다.

PC는 기존 탐색 구조를 재사용하고, 홈은 상태·식사 기록·추천 진입을 넓게 배치한다. 결과 화면은 음식 확인과 영양 요약을 나란히 배치하고 모바일에서는 세로로 쌓는다. 고정 하단 메뉴가 저장 버튼이나 입력 필드를 가리지 않게 한다.

전체 화면에 로딩, 빈 상태, 오류·재시도, 세션 만료 처리를 정의한다. 사용자 날짜·끼니 집계는 Asia/Seoul 기준이다. 숫자에는 kcal, g, mg 단위를 붙인다. 누락된 영양값을 0으로 위장하지 않는다.

초록·크림·민트 중심의 색, 둥근 카드, 음식 사진, 지방이 일러스트를 참고한다. 색상 코드·글꼴·여백은 후속 디자인 제안으로 검토하며 이번 문서에서 확정 토큰을 만들지 않는다. 색만으로 상태를 전달하지 않고 텍스트를 함께 제공한다. 아이콘 버튼에 이름을 제공하고 키보드 사용·초점 표시·확대 화면을 검수한다.

## 5. WEB APP — 화면별 상세 지시

### APP-01 로그인 / 회원가입

- 구성: 로고, 지방이 안내, Google 시작, 이메일·비밀번호, 로그인, 회원가입, 비밀번호 찾기.
- 기존 이메일 인증·Google 인증·비밀번호 재설정·HttpOnly 세션을 재사용한다. 만 18세 정책과 기존 동의 절차를 유지한다.
- 로그인 성공 후 기존 프로필을 확인해 홈 또는 목표 설정으로 이동한다. 인증 오류는 입력을 유지하며 재시도할 수 있게 한다.
- Google 실인증 검증 상태와 로컬 테스트 상태를 구분한다. 선택 동의는 필수 동의와 분리하고 문구 미확정 상태를 임의 승인하지 않는다.
- 완료 기준: 이메일 로그인·로그아웃·재로그인과 기록 유지, 비밀번호 찾기 경로, 미인증 데이터 접근 차단.

### APP-02 홈 대시보드

- 구성: 인사, 선택 날짜·주간 달력, 지방이 안내, 섭취 열량/목표, 실제 탄단지·당류·나트륨, 끼니 카드, 식단 기록·분석·추천 진입.
- 날짜 변경 시 해당 날짜의 저장된 사진·음식·영양 합계를 조회한다. 빠른 날짜 전환에서 이전 응답이 최신 화면을 덮지 않게 한다.
- 목표 미설정은 목표 설정으로 안내한다. 목표 초과는 실제 수치를 표시하며 평가·벌점·절식 유도를 하지 않는다.
- EXP 활성화 시에만 지방이 미션·포인트·streak 위젯을 추가한다. 비활성화 상태에서도 식단 기능을 사용할 수 있어야 한다.
- 완료 기준: 날짜별 합계가 저장 기록과 일치, 과거 기록과 오늘 기록 구분, 빈 기록에서 분석·수동 기록 진입 가능.

### APP-03 음식 사진 분석

- 구성: 사진 선택/촬영, 미리보기, 교체·취소, 분석 실행, 진행 상태, 수동 음식 선택.
- 기존 `PhotoInput.jsx`와 탐지 API를 먼저 확인한다. 브라우저에서 촬영을 지원하지 않거나 권한이 거절되면 파일 선택으로 진행한다.
- 허용 형식·용량은 현재 서버 검증과 일치시킨다. 지원하지 않는 이미지·분석 실패·음식 미탐지는 각각 안내한다.
- 여러 음식의 탐지 ID·라벨·confidence·bbox 연결을 유지한다. 분석 결과만으로 식단을 자동 저장하지 않는다.
- 완료 기준: 정상 사진, 다중 음식, 미탐지, 잘못된 파일에서 확인 화면 또는 수동 경로로 이동.

### APP-04 분석 결과 및 수정

- 구성: 사진, 음식별 탐지 결과, 음식 수정/추가/제외, 기준 섭취량·배수, 영양 요약, 날짜·끼니, 저장.
- `ScanResult.jsx`, `NutritionSummary.jsx`와 기존 Python 계산을 재사용한다. 1인분의 g 값을 이미지에서 추정해 확정하지 않는다.
- 음식·섭취량 변경 후 Backend 계산값을 갱신한다. 기존 식품 기준량과 단위를 표시한다.
- 합계에는 열량·탄단지·당류·나트륨을 제공한다. 탄단지 그래프의 4/4/9 환산 구성비와 목표 달성률을 구분한다.
- 저장 중 중복 제출을 막고 실패 시 수정값을 유지한다. 저장 성공 후 홈·식단 조회에 반영하고, 후속 조회 실패가 성공한 저장을 취소한 것처럼 보이지 않게 한다.
- Correction은 식단 저장 transaction과 기존 동의·QA 경로를 따른다. 수동 음식은 detection 연결이 없을 수 있다.
- 완료 기준: 다중 음식 수정·섭취량 계산·저장·재조회 일치, 타인 detection ID 사용 차단, 실패 후 재시도.

### APP-05 식단 기록

- 구성: 날짜 이동, 아침/점심/저녁/간식 구분, 음식·사진·섭취량, 일일 합계, 음식 추가, History 표 이동.
- 홈의 선택 날짜와 기록 화면의 날짜를 일관되게 전달한다. 이미지 없는 수동 기록도 표시한다.
- 음식 수정·삭제 버튼은 현재 API 지원 여부를 확인한다. 지원이 없으면 후속 작업으로 정의하며 기능 완료를 주장하지 않는다.
- 수정·삭제를 확장 구현할 때 일일 합계, 추천 snapshot, 보상 이벤트 영향을 함께 설계한다.
- 완료 기준: 검색·끼니 필터·날짜 정렬을 보존하고 모바일에서도 기존 History 표를 조회할 수 있음.

### APP-06 맞춤 식사 추천

- 구성: 현재 상태 요약, 추천 메뉴 3개, 출처 있는 영양값, Rule 기반 이유, 상세·기록 CTA.
- 시안의 `추천 메뉴 / 간단 식단 / 오늘의 조합` 탭은 제안이다. 각 탭의 데이터와 조합 계산이 없으면 기본 추천만 노출한다.
- 기존 추천 service와 필터·다양성·최근 반복 처리 사용. 미확정 탄단지·당류·나트륨 목표로 부족·초과를 판정하지 않는다.
- 추천 선택 → 날짜·끼니·섭취량 확인 → 실제 저장 성공 → acted 갱신 순서다. 클릭만으로 섭취 기록을 만들지 않는다.
- 출처 없는 음식 사진과 영양 수치를 실제 후보처럼 제시하지 않는다. 이미지 사용 권한도 후속 자산 검수에 포함한다.
- 후보가 3개 미만인 경우 처리 정책은 TBD다. 출처 없는 후보로 수를 채우지 않고 기존 동작을 확인한 뒤 정책을 결정한다.
- 완료 기준: 데이터 출처·추천 이유·실제 기록 연결, 개인별 조건 적용, 추천 실행 실패 안내.

### APP-07 지방이 성장 & 포인트 — EXP-A

- 구성: 현재 지방이, 성장 단계, 다음 해금 조건, 실험 포인트 잔액, 미션, 꾸미기, 거래 내역.
- 성장의 의미는 습관 축적에 따른 표정·소품·배경 변화다. 체중 감소·낮은 섭취량·운동 상쇄량을 성장 조건으로 삼지 않는다.
- 시안의 Lv.1~Lv.4를 초기 표현 후보로 사용한다. 단계 수·EXP 산식·보상량·적립 상한은 TBD다.
- 꾸미기 흐름: 아이템 목록 → 보유/잠금 확인 → 미리보기 → 구매 또는 해금 → 착용 → 재접속 후 상태 유지.
- 해금과 구매를 구분한다. 보유하지 않은 아이템 착용·음수 잔액·중복 차감을 차단한다.
- 프로토타입의 샘플 포인트는 실제 자산이나 교환 가능한 보상으로 표시하지 않는다.
- 완료 기준: 아래 원장·중복 방지 기준 검증 후 내부 실험 완료로 표시. 공식 P0 완료 기준에는 포함하지 않음.

### APP-08 내 기록 / 통계

- 구성: 기간 선택, 열량 추이, 실제 영양 섭취량, 식단 표, 사진 기록, 프로필·목표·동의·비밀번호 설정.
- 주간/월간/전체 탭은 지원 가능한 조회 기간과 함께 구현한다. 기록 없는 날을 미기록으로 표시하며 실제 0 kcal 기록과 구분한다.
- 그래프 축·단위·기간·날짜를 표시하고 표 또는 수치로도 확인할 수 있게 한다. 목표 미설정 시 달성률 링을 표시하지 않는다.

- 완료 기준: 합계와 표 일치, 기간 경계·KST 확인, 로그아웃 시 개인 기록 제거, 재로그인 후 서버 기록 복원.

## 7. EXP-A 데이터 및 보상 설계 초안

다음은 후속 설계 후보이며 이번 작업에서 테이블·migration·API를 생성하지 않는다. 실제 기존 schema와 충돌 여부를 확인하고 A 담당자가 migration을 관리한다.

## 8. 추가 확장 축

v5.2의 아이디어를 유지하되 화면 시안과 핵심 기록 흐름에 연결한다.

- 운동 추천(P1): 사용자 입력 활동량·시간·선호 → 출처 있는 운동 후보 → Rule 기반 3개 추천. LLM 설명은 선택적인 후속 단계이며 실패 시 Rule 설명 유지. 웨어러블 연동은 별도 단계다.

- Feed·Follow(EXP-B): 공개를 사용자가 선택하고 체중·목표·민감 기록은 기본 비공개. 게시 전 공개 항목을 확인하며 신고·차단·삭제·댓글 운영을 함께 검토한다.
- Challenge·Ranking(EXP-B): 기록·지속·참여 중심. 체중 감소·절식·과도한 운동량 순위를 만들지 않는다. 기간·집계·동점·부정 참여·중도 탈퇴 정책은 TBD다.
- Coach(EXP-C): 자격 검수·회원 공유 동의·조회 범위·연결 해제 이후 접근 차단을 정의한 후 피드백 실험. 일반 사용자 admin 승격으로 구현하지 않는다.
- Creator·제휴(EXP-D): 광고·협찬 표시, 콘텐츠 출처, 공개 범위, 브랜드 아이템 권리 확인 후 검토. 포인트의 현금성·쿠폰 교환은 별도 사업 정책이다.

## 9. 모델 실험 계획 보존

v5.2의 YOLO26m / YOLO11m 비교는 별도 실험 계획으로 유지한다. 기존 best.pt와 원본 CSV·YAML은 보존한다. 데이터 split, seed, epochs, imgsz, batch, optimizer, augmentation, device, test set을 맞추고 모델별 불가피한 차이를 기록한다.

비교 항목은 mAP50, mAP50-95, Precision/Recall/F1, 추론 시간, 파일 크기, 혼동 사례, 영양 매핑 성공률, 사용자 보정 이후 기록 완료율이다. 정확도 하나만으로 교체하지 않는다. 학습 결과 폴더·args·weights·곡선·confusion matrix를 모델별로 보관하며 모델 교체는 별도 검토 후 진행한다. 이번 문서 작성으로 학습이나 교체를 실행하지 않는다.

### 13.2 PC 홈과 탐색

시안 B의 사이드바 후보는 홈 / 식단 기록 / 추천 식단 / 운동 기록 / 대시보드 / 내 지방이 / 설정이다. 기존 PC 와이드 배치를 유지하면서 기능을 묶는 참고안으로 사용한다. 운동·캐릭터 항목은 해당 실험이 활성화된 경우에 노출한다. 기존 화면으로 가는 접근을 없애지 않는다.

하단 식단 기록 2/3·운동 1/1·물 6/8·체중 기록 카드는 행동 요약 제안이다. 식단의 분모 3을 모든 사용자 목표로 고정하지 않는다. 물의 단위·한 잔 용량·목표·시간·수정/삭제, 체중의 단위·입력 주기·공개 범위·추세 계산은 TBD다. 해당 데이터 저장 기능이 없으면 실제 기록인 것처럼 표시하지 않는다.

### 13.3 월간 캘린더와 상세 통계

월 이동 → 날짜 선택 → 해당 날짜의 끼니·음식·사진·영양 합계 순서로 연결한다. 주간 홈과 월간 캘린더는 같은 KST 날짜·저장 자료를 사용한다. 날짜 표시·오늘 표시·기록 있음 표시를 구분하고, 달 변경·빈 날짜·오류·빠른 선택 전환을 처리한다. 과거 날짜 추가는 기존 저장 API 지원과 정책 확인 후 제공한다.

캘린더는 기존 음식별 History 표의 추가 진입 화면이다. 표 검색·필터·정렬을 보존한다. 큰 사진 카드에는 끼니·음식·실제 섭취량을 표시하고 `식단 추가`는 선택 날짜·끼니를 확인하게 한다.

상세 대시보드의 영양 요약 탭은 기간별 실제 영양값·열량 추이·구성비를 제공한다. B의 탄단지 45/30/25%는 확정 목표가 아니다. 그래프가 실제 섭취량의 열량 환산 비율이면 그 의미를 명시한다. 식단 탭은 기존 History, 운동과 체중 탭은 저장 기능이 구현된 이후 연결한다. 일반 사용자의 상세 대시보드와 관리자 QA 화면은 권한과 목적을 구분한다.

### 13.4 운동·꾸미기·설정 보완

운동 카드의 빠르게 걷기·하체 근력·실내 자전거는 UI 예시다. 운동 시간·난이도·장비·장소·추천 이유를 출처 있는 데이터와 사용자 조건으로 제공한다. 이미지의 150/180/200 kcal를 하드코딩하지 않는다. 소모 열량을 제공하는 경우 계산 근거·입력·추정 여부를 별도 검토한다. 영상 재생 아이콘은 재생 가능한 허가된 콘텐츠가 있을 때만 활성화한다.

지방이 화면은 기본형 → 소품 선택 → 미리보기 → 착용 확정 흐름으로 계획한다. 단계별 모습은 작은 지방이가 더 큰 체형이 되는 평가 구조가 아니라 의상·표정·소품·배경 변화로 표현한다. 운동복·물병은 운동량 경쟁을 보상하는 의미로 사용하지 않는다.

설정은 내 정보, 목표 설정, 동의, 비밀번호 변경, 로그아웃을 기존 기능에 연결한다. 알림 설정·계정 삭제는 실제 기능과 운영 정책을 확인한 뒤 추가한다. 계정 삭제와 로그아웃을 구분하며 삭제 시 사진·기록·원장·공개 콘텐츠 처리와 재인증은 후속 정책으로 남긴다.

### 13.5 홈페이지 시안 B 통합

B의 메인 / 주요 기능 / 지방이 소개 / 이용 방법은 각각 WEB-01/03/04/05의 대안이다. 서비스 소개는 기존 WEB-02를 유지할 수 있고, 가격 구성은 A에만 있으므로 사업 검토 상태를 유지한다. 메인 캐릭터를 우측에 크게 두는 구성과 기능 4개 카드는 PC 참고안이며 모바일에서는 자연스럽게 쌓는다.

홈페이지 메뉴의 건강 레시피·자주 묻는 질문은 후속 콘텐츠 후보로 추가한다. 레시피는 출처·재료·기준량·영양 데이터가 검증된 뒤 제공하고, FAQ는 실제 제공 기능·인증·기록·사진 처리 기준에 근거해 작성한다. 이미지의 `다운로드(웹앱)` 표현은 설치 기능이 확인되지 않은 상태에서는 웹앱 시작 링크로 계획한다. PWA나 앱스토어 배포를 새로 지시한 것으로 해석하지 않는다.

홈페이지에서 운동·챌린지·지방이 성장이 이미 제공되는 것처럼 설명하지 않는다. 현재 제공 기능·내부 실험·준비 중 기능을 구분해 표현한다. 최종 화면 검수에는 시안 A/B 대응표, 선택한 배치, 실제 데이터 여부, 남은 TBD를 함께 기록한다.
